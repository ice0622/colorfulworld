# アップロードはサーバルート維持し、メタデータをバッファから生成する

バッチ/複数アップロードでも、クライアント直 Blob アップロード（`@vercel/blob/client`）へは移行せず、既存のサーバルート `POST /api/admin/upload`（`put()` で Blob 保存）を維持する。理由: 今回アップロード時に sharp で寸法と blur を生成して `media` に保存するが、サーバルートは「受け取ったバッファ」からそのまま sharp を回せる。クライアント直アップロードにすると、メタデータ生成のために保存後の Blob を再 fetch する無駄が生じる。クライアントは従来どおり事前に HEIC→JPEG 変換＋1920px 縮小するため、アップロード実体は数百KBに収まり Vercel の 4.5MB ボディ制限にも掛からない。

## Consequences

- アップロード進捗は fetch ベースのため、真のバイト単位%は出さず「状態チップ＋件数＋経過タイマー」で示す（バッチ時の待ちは実質クライアント側の HEIC 変換が支配的で、そこにバイト%は元々出せない）。
