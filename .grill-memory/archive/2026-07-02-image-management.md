# Grilling: 画像管理（バッチアップロード＋画像ライブラリ） 2026-07-02

## 出発点（ユーザーの不満・要望）
- CMSの画像アップが一枚ずつでストレス。
- 一度上げた画像が再利用できない。
- 記事に簡単に画像を上げたい。スマホからのアップが主。
- 複数選択でまとめてアップ→順番で自動挿入。
- アップ中の所要時間/進捗を把握したい。
- 記事から誤って消しても再アップ不要にしたい→URL文字列を貯める画像一覧ページが欲しい。

## Q&A（決定事項）
- Q0 前提: 現行自作CMS(Neon+Blob)に追加。旧R2案は破棄。→ 「旧案コードがあれば消して」。調査結果: **旧案コードは不在**（docのみ）。
- Q1 ライブラリの source of truth → **新規 media テーブル(Drizzle)**。
- Q2 アップ時メタデータ → **sharp で w/h+blur を生成して media に保存**。
- Q3 公開表示側のマニフェスト統一（アップ直後blur） → **今回は延期**（表示はビルド時マニフェストのまま）。
- （前提確定）アップ経路 → **サーバルート維持**（バッファから直接sharp。クライアント直Blobは再fetchの無駄）。
- Q4 進捗表示 → **状態チップ＋件数＋経過タイマー**（真のバイト%バーは作らない、fetch維持）。
- Q5 並列度 → **少数並列（同時2〜3件）**（HEIC変換のメモリ圧を考慮）。
- Q6a 挿入位置 → **カーソル位置に順番で**（カーソル未確定時は末尾フォールバック）。
- Q6b ライブラリUI → **エディタ内ピッカー＋独立 /admin/images 一覧ページの両方**。
- Q7 ライブラリ削除 → **ソフト削除（非表示化のみ、Blob実体は残す）**。
- Q8 既存画像バックフィル → **Blobの62枚だけ**（ローカル163は対象外）。
- Q9 掃除 → **旧エディタの死コード（MarkdownTextarea.tsx / LivePreview.tsx）のみ削除**。docは残す。
